# marklab 需求规格

> 这份文件说「系统应该怎样」；`README.md` 说「现在怎么用」；
> **`docs/site-pack.md` 说「站点包必须有什么」**（那一块以它为准，本文只管需求）；
> `docs/adr/` 说「为什么这么定」。
> 其余冲突时以本文件为准，然后改其它几份。
> 术语一律照 `GLOSSARY.md`，不另造词。
>
> 每条规则都要能被 `§11 验收标准` 里的一条命令验掉；验不掉的规则不写在这里。

## 1. 一句话

把四个 3D 模型站（创想云 / MakerWorld / Snapmaker / MakerOnline）的模型抓回本地，
统一成一份能看、能下、能搜的库；抓取要慢到不被封，判重要准到不误删。

### 不做的事

- 不做账号体系、不做多用户、**不做鉴权**（用户明确决定，控制台只在本机用；因此服务不得暴露到公网）。
- 不做站点的写操作：不点赞、不评论、不下载许可范围内的付费件。
- 不做实时同步：库是快照，不追站点的后续修改。
- 不引第二个 npm 依赖（ADR-0002）。
- 不把点赞/收藏/评论/评分/许可证写进 `library/`（订阅按点赞数筛是例外，记在 `data/`）。

## 2. 站点包

每个站点一个独立包，**不许在公共层写 `if (site === ...)`**。MakerOnline 的 `.cn` 和 `.com`
是**两个各自独立实现的包**（字段、登录态、接口都不同，不抽公共层，接受约 250 行重复）。

现在的六个包：`snapmaker` / `creality` / `makerworld` / `makeronline.cn` / `makeronline.com` / `makeroad`
（`sites/index.mjs` 登记）。包有两个名字，别混：

- `site`（包键）：区分域名，登录态、cookie、请求头按它取。`makeronline.cn` 与 `makeronline.com` 不同。
- `platform`（数据键）：库目录、判重键、进度用它。**必须一个域名一个键**——`.cn` 和 `.com` 是两套
  独立 id 空间（2026-11-02 实测 makerworld 同号 1014649/195581/1309981 两域是完全不同的模型，
  MakerOnline 同理，审核规则也不同），共用键会让两个站的模型落进同一个库目录、撞同一个判重键。
  所以 `platform` 一律写成域名：`makeronline.cn` / `makeronline.com`。
- **一个站点包只认一个域名**。`makerworld` 包只认 `makerworld.com.cn`：`makerworld.com` 是另一个站，
  要接就另开一个包（照 `makeronline` 的先例），不许把域加进现有包的 HOSTS。
- 别名：`makeronline` 落到 `.cn` 包（老订阅/手输的历史键，默认不把海外站算进搜索预算）。
  别名只在**入口**认；`search()` 返回的 `site` 一律换成包的规范键，否则和库里的 `${platform}:${id}` 对不上。
- `categoriesKey` 是「分类 id 空间」的键，不是数据键：MakerOnline 两域各有一套分类 id，
  对照表（`docs/categories/merge.json`）以海外站的 id 为准，两包都写 `categoriesKey: 'makeronline'`。

一个站点包必须提供什么、每个成员收什么返什么、没有的能力怎么写、限速三层怎么覆盖——
**全部以 `docs/site-pack.md` 为准**（唯一契约）。这一节只管命名和网址规则。

- 必需成员五个：`match` / `loginState` / `meta` / `fileLinks` / `search`。
- 可选成员四个：`checkin` / `userModels` / `categories` / `status`。
- **「没有」= 键不存在**，不写 `null` 占位；公共层用 `typeof pack.x === 'function'` 判断，
  **不许按站点名判断**。

### 2.1 网址处理（硬规则）

1. 先 `new URL(raw)`；解析失败直接拒绝。
2. **`hostname` 必须命中该站点白名单的精确值**（`www.crealitycloud.cn`、`makerworld.com`、
   `makerworld.com.cn`、`space.snapmaker.cn`、`www.makeronline.com`、`www.makeronline.cn` …），
   不许用 `endsWith` 或整串正则判断。
3. 正则只跑 `pathname`，不跑整串 URL。
4. 抓取时**只用重组后的 canonical 网址**，绝不用用户传来的原始串——原始串的 query/fragment
   里可以塞另一个站点的网址，`http://evil/x#https://真站/model-detail/<id>` 现在会被认成真站，
   并让服务端去请求 `evil`。
5. 认不出的网址一律拒绝入队，错误信息说清楚「哪个站都不认识」。

### 2.2 解析点不许求值远端 JS

四个解析点（`__NUXT_DATA__` / `design-service` / `api-models` / Snapmaker RSC 载荷）只允许
**JSON 解析 / 正则 / 浏览器页内取数**。禁止在服务端 `eval` / `vm.runInContext` / `new Function`
执行站点返回的脚本——`vm` 不是安全边界（实测 `this.constructor.constructor("return process")()`
能拿到宿主进程）。

站点只给一段 JS 字面量（如 `window.__NUXT__=(function(){…})(…)`）时，用真浏览器页内取值，
或换一个 JSON 接口；两条都不行就放弃这个解析点并在 README 记为已知边界。

### 2.3 站点文本一律不可信

描述、评论、作者名这类站点给的富文本**两边都要洗**：

- **抓取侧洗一遍再存库**（白名单：只留排版标签，属性只留 `href`/`src`/`alt`/`width`/`height`，
  链接只放 `http/https/mailto`，图片另放 `data:image/`）。库里存的必须是干净的，
  否则任何读库的程序都得自己再洗一遍。
- **渲染侧再洗一遍**（解析成 DOM 后按白名单重建，不用 `innerHTML` 直接插）。
  库里干净不等于渲染安全——老数据是旧规则洗的，脚本改坏了也看不出来。
- 白名单是**只允许列出来的**，不是「删掉危险的那些」：黑名单永远漏（`<img/src=x/onerror=…>`
  没有空格、`javas&#99;ript:` 实体编码，两种都实测绕过）。

## 3. 流程

```
入队 → 排队（每站一队，轮转）→ 抓元数据 → 判重（前置）→ 下文件 → 判重（后置）→ 落盘 → 索引
```

### 3.1 入队

- 三种来源：手动（粘贴网址）、订阅（关键词/作者）、批抓（榜单）；补抓是第四种，走手动通道。
- **同 URL 已在队列或正在跑 → 不重复入队**，返回既有任务。
- **24 小时内成功跑完过**（`done`/`duplicate`）→ 不重复入队，返回既有任务（连点两次不该白等一次闸门）。
- **失败 / 中断 / 停止过 → 允许重新入队**：用户再点一次就是「再试一次」的意思，不许静默返回旧失败结果。
- 入队只做 §2.1 的网址校验，不做站点可达性检查（那要花一次请求）。
- **暂停时照样能入队，但不解除暂停**：手动入队的任务打 `force` 标记，只放行它自己先跑，
  队列里其它任务继续停；跑完标记清掉，队列自然回到暂停。
- **手动加的链接一律插队**：插到它那个站的队首，并把轮转指针指过去，所以下一个跑的就是它
  （暂停中同样如此，见上一条）。插队只改排队顺序，**不豁免闸门**——上一个任务结束后该等的
  60–120 秒照等，不会因为「人点了」就连发。
- 所有入队路径（手动/订阅/批抓/补抓）必须走同一个校验函数，不许各写一套。

### 3.2 排队

- **每个站点一个队列**，按轮转取下一个，避免一个站饿死其它站。
  手动加的链接（§3.1）插到**它那个站**的队首并把指针指过去，下一个就跑它；不打断正在跑的，
  也不动别的站的队。
- **全局串行**：同一时刻只有一个 `grab` 子进程；限速状态与队列是**同一份**、有单写者。
- **浏览器全局并发 1**：只有一个写者能连 CDP 9223。并发连会把连接拖到超时，然后标签泄漏，
  然后更慢（实测：单客户端 20 秒，5 个并发全部超时）。服务端自己的登录探测、搜索取页、
  批抓进程都算写者，必须排同一个队。
- **标签页只在 `channel.mjs` 开和关**：别的文件不许自己 `newPage()`。重连（`forget()`）和
  脚本退出（`exit()`）都必须先关自己开的页——只清 Map 不关页，用户浏览器里会攒出一排窗口
  （实测：每点一次「登录状态刷新」漏一个）。关掉最后一个标签页 Chrome 会连着退出，
  所以 `closePages()` 先垫一张空白页再关。
- 子进程必须有**墙钟上限 30 分钟**：超时先 `SIGTERM`（让它关掉自己开的标签页），
  5 秒后还没退再 `SIGKILL`，按失败处理，并把「超时」写进任务错误。
  **不许直接 `SIGKILL`**——那会把标签页留在用户浏览器里（ADR-0005 补记 11）。
- `data/queue.json` 存**排队 id 列表 + 暂停位 + 下次可开跑时间**。
  任务本体唯一真相在 `data/tasks/*.jsonl`；`queue.json` 只是队列成员的指针，不存任务本体
  （存两份必然分叉，且没有仲裁规则）。
- 重启按 `queue.json` 恢复：暂停仍是暂停，间隔没走完不许开跑，只恢复名单里那些 id
  （**归属就是排队名单本身**，不在 jsonl 行里记 `owner`——pid 会复用，历史行也没有这个字段）。
  id 在 jsonl 里找不到就跳过，不许因此阻塞恢复。

### 3.3 抓元数据

- 四个解析点是唯一入口；站点改版只改适配器，不在页面里打补丁。
- 解析失败 = 本次失败，可重试；不许写入半截 `model.json`。
- 登录态只影响「能不能下文件」，不影响元数据（元数据一律匿名抓）。

### 3.4 下文件

- 先问站点包要文件链接，再逐个下载。
- **单个文件失败不拖累其余**：48 个文件的模型不能因为第 3 个挂了就全丢；失败的个数要落字段（§4.4）。
- 下载先写 `<目标>.tmp` 再 rename（与其它 JSON 落盘**同一套原子写**，不另造 `.part` 概念），
  **不许留半截文件**；响应带 `Content-Length` 时核对字节数，对不上重下一次。
- 单个文件不设大小上限（3mf 见过 173 MB），但 `savedFiles[].bytes` 必须记，磁盘用量靠它汇总。
- 一个都没下到时要记原因（`noFiles`，§4.4）。
- 浏览器没连上时**不许**把匿名 CDN 文件也算失败——公开直链不该走登录态通道。

### 3.5 落盘

```
library/<platform>-<id>/
  model.json
  files/<序号>-<slug>.<ext>
  img/01.jpg ... img/plates/01.webp
```

- 目录名只由 `platform` + 站点 id 决定，重抓写回同一个目录。
- **所有 JSON 落盘都走 `tmp + rename`**（`model.json`、`subs.json`、`duplicates.json`、
  `tags.json`、`queue.json`、`llm.json`），不许写一半。半截 `model.json` 会让模型在判重索引里
  静默消失，并被当新模型再抓一遍。
- `library/` 是数据：只允许「新建目录」「重抓覆盖同一目录」「打标签只增补 `llmTags`」，
  不许改别的字段，不许删别人的目录。
- 预览缓存（3mf 盘图、解析结果）是派生数据，**放 `data/preview/<platform>-<id>/`，不写进库目录**：
  库目录是备份与迁移的单位，混进可再生的派生数据会让「库多大」失去意义；
  删模型时连派生数据一起删。
- **失败怎么处置**：跨站 hash 确认重复 → 删掉本次目录；其它失败**保留**已经下到的文件与图片，
  下次重抓覆盖同一个目录。解析失败不写 `model.json`（宁可没有模型，不要半截模型）。
- **备份与迁移的单位是 `library/`**：拷走整个目录就是完整备份（`data/` 是可重建的状态，
  唯一例外是 `data/ipwatch.json` 与 `data/tags.json` 里人写的内容）。换机器 = `library/` + 这两个文件。

### 3.6 索引与展示

- 服务启动时扫 `library/`，之后以文件系统状态为准，不额外维护索引文件。
- 列表接口只发卡片字段（§9.1），**带 60 秒缓存**；详情按需再拉一份完整数据。
- **缓存必须在写操作后主动失效**：抓取完成、删模型、打标签、补抓之后立刻清——
  否则用户刚抓完一个模型，列表里看不见它。
- 进程内的判重索引与订阅缓存同样要能失效：`grab` 落盘后 `index(true)`，订阅每轮开始 `load(true)`。
  不失效的后果不只是「看不见」：下一次 `persist()` 会把别的进程刚写的内容整份覆盖掉。

## 4. 数据契约

### 4.1 `model.json` 字段

**适配器必写**：`platform` `id` `sourceUrl` `title` `author` `description` `images`
`fetchedAt` `stats` `files` `savedFiles` `profiles` `print` `category` `tags` `autoTags`

**条件写**：`localImages` `docs` `rawFiles` `siteOnlyFiles` `fileIds` `activeProfileId`
`noFiles` `duplicateOf` `translated` `via` `site` `authorUid` `authorAvatar` `publishedAt` `picked`

- 站点没有的字段留空，不许编造（宁可空，不要假数据）。
- 站点不提供的配置（比如 Snapmaker 没有机型）就是空数组，不用兼容字段凑。
- `savedFiles[]` 每项：`name` `path` `bytes` `sha256` `kind` `origin`，另有可选的 **`profileId`**——
  **配置与本地 3mf 的唯一对应关系**（`kind: 'profile'` 且站点给了配置 id 时写：创想云 `p.id`、
  MakerWorld `fileIds[i]`、MakerOnline `print_profile_id`）。历史数据没有这个字段，
  按 §4.2 的降级规则推断。
- `via` 记录取数来源：`api`（匿名公开 API / node 直连）或 `channel`（真浏览器页内取数）。
  目前只有 MakerWorld 的 `meta` 写这个字段（`api`）；`channel` 是给将来仍在页内取数的站留的取值，
  现有五站的 `meta` 都不写它。只是多一个取值，不新增字段。
- **新增字段必须同时进本表**，否则算未定义字段。必填键由 `sites/contract.mjs` 的 `isModelMeta()` 守着（契约测试跑它），多余字段不查——`grab.mjs` 会往上加。
- **历史数据缺字段按默认值解释，不做批量迁移**：`origin` 缺省算 `author`，`noFiles` 缺省算
  `unknown`（老数据没这个字段），`via` 缺省算「来源不明」。只有字段语义变了才写一次性脚本，
  脚本必须支持 `--dry` 并原子写回。

### 4.2 `profiles[]`

每项：`name` `machine` `machines[]`（字符串数组） `plates` `plateList[]` `timeSec` `timeText`
`weightG` `nozzle` `layerHeight` `wallLoops` `infill` `filaments[]` `isDefault` `thumbnail` `url`

**作者身份**（§4.3 用它算 `origin`）四站键不同，不强行归一：

| 站点 | 配置作者 | 模型作者 |
|---|---|---|
| 创想云 | `isAuth` | 同字段 |
| MakerWorld | `instanceCreator.uid` | `designCreator.uid` |
| MakerOnline | `is_author`（页面上的 Designer 徽标） | 同字段 |
| Snapmaker | `printProfiles[].creatorId` | 模型 `creatorId` |

`print.machines` 是**对象数组**（`{name, code, nozzle}`），`profiles[].machines` 是**字符串数组**——
两种形状都是契约的一部分，不许互相"统一"。

**配置 ↔ 本地 3mf**：优先 `savedFiles[].profileId === profiles[].id`（**一律按字符串比**，
站点 id 有数字有字符串）。历史数据缺 `profileId` 时按顺序降级：① 配置名与文件名精确匹配；
② 模型只有一条配置、一个本地 profile 文件时直接对应；③ 都不成立就不给本地文件，
按钮指回站点原帖（带 `#profileId-`）。**不许按顺序硬配**——A 配置的 3mf 塞给 B 配置比没有更糟。
MakerOnline 多条配置常指向同一个 3mf，`fileLinks` 按对象路径去重，共用一份不算错配。

### 4.3 文件来源 `origin`

| 值 | 含义 | 参与判重 |
|---|---|---|
| `author` | 作者自己上传的（**含作者自己发布的打印配置**） | 是 |
| `other` | 别人给这个模型做的打印配置 | 否 |

- 判定规则见 §4.2 的作者身份表；认不出谁是作者时按 `author` 算（宁可多比，不要漏比）。
- 历史数据里 `origin` 可能缺失，缺失按 `author` 算。
- `origin: 'profile'` 已废弃，不再产出；见到就按 `author` 处理。

### 4.4 无文件原因 `noFiles`

| 值 | 含义 | 处理 |
|---|---|---|
| `login` | 站点要登录才给文件 | 登录后统一补抓 |
| `captcha` | 站点要人机验证（目前只有 MakerWorld：418 + geetest） | 在浏览器里打开该模型页过一次验证，再补抓 |
| `parse` | 有文件但解析没拿到链接 | 修解析器，然后重抓 |
| `none` | 站点本来就不提供下载 | 不再重试 |
| `skipped` | 这一轮压根没尝试下载（`--no-files`） | 不算问题 |

**不变量**：`savedFiles` 非空时不许有 `noFiles`；重抓拿到 0 个文件时，`noFiles` 按本轮原因写，
旧的 `savedFiles` 保留并按磁盘实际存在过滤。

部分失败单独记：`filesFailed: <个数>`（有值即表示「下到一部分」），此时 `noFiles` 不写。

### 4.5 判重记录 `data/duplicates.json`

```json
{
  "creality:abc": {
    "of": "makerworld:123",
    "by": "hash",
    "scope": "cross",
    "at": "2026-10-30T07:00:00.000Z",
    "title": "…", "author": "…", "url": "…", "platform": "creality",
    "hashes": ["<撞上的作者件 sha256>"]
  }
}
```

- `scope`: `same`（同站标题+作者，**确认重复**）/ `cross`（跨站，`by:hash` 才是确认）。
- `by`: `meta`（标题+作者相同）/ `hash`（作者件字节相同）。
- 页面文案按 `scope`+`by` 组合出，不许把同站确认也写成「疑似」。
- 库里不留重复文件，但**证据要查得到**（`hashes` 只写真正撞上的那几个）。
- 详情页在配置卡下方列出「同模型链接」，指向库内另一份或站点原帖。
- 删模型时同步清掉 `duplicates.json` 里指向它的条目（不留悬空链接）。

### 4.6 标签与分类

三套标签各管一件事，不许混：

| 字段 | 来源 | 谁写 | 重抓时 |
|---|---|---|---|
| `tags` | 站点原标签 | 适配器 | 覆盖 |
| `autoTags` | 规则（精选 / 热门门槛，`lib.mjs`） | 适配器 | 覆盖 |
| `llmTags` | 大模型从标签池里挑 | server（唯一例外：只增补这个字段） | **保留** |
| `cat` | 原站分类名映射（`lib.mjs` `catIndex`/`catOf`） | 服务端派生 | 每次重算 |

- 分类按**原站分类名**映射，不自己发明；同名歧义归「未分类」，不硬猜。
- 大模型只许从标签池里挑词；池外的新词进 `data/tag-pending.json` 等人确认，不许直接写进 `model.json`。
- 打标签是**花钱且不可逆**的操作：同一批不许并发跑两次（单飞），控制台要显示进度。
- 分类对照表在 `docs/categories/`：`sites.json` 是抓来的原站分类，`merge.json` 是**人**的合并决定，
  `对照表.md` 是生成给人看的。脚本只重写 `sites.json` 与 `对照表.md`，
  **永远不碰 `merge.json`**——脚本覆盖人的决定，下次就没人敢改了。

### 4.7 其它数据文件

`data/` 下的状态文件都是**可重建的**（库才是资产），但形状要固定：

| 文件 | 形状 | 写者 |
|---|---|---|
| `subs.json` | `{ subs: [{ id, name, kind, keywords[], users[], rules[], feeds[], matchModes[], minLikes, minDownloads, pickedOnly, intervalHours, enabled, cursor, lastRunAt, lastResult, authorCursor }] }`（`rules[]` = `{ site, sort, limit, filters }`，`filters` 可为 `null`；`feeds[]` = `{ site, feed, limit }`；作者订阅不带 `rules`/`feeds`/`matchModes`/`minLikes`/`minDownloads`/`pickedOnly`，改用 `authorCursor: { "site:id": { page, done } }`；榜单订阅只带 `feeds`） | server |
| `subs/<id>.candidates.json` | `{ items: [{ key, sources[], title, author, tags[], decision, firstSeen, lastSeen }] }`，键是 `site:id`；`decision` ∈ `queued / no-match / threshold / in-library / in-queue`；30 天没再出现就清 | server |
| `subs/<id>.jsonl` | 每行一条命中：`{ url, title, author, site, likes, downloads, matchedAt, taskId }`，新的在前 | server |
| `tasks/<YYYY-MM>.jsonl` | 每行一条任务快照（全量覆盖式，按 `id` 取最后一行）：`{ id, url, site, source, subId, phase, rounds, progress, error, warning, startedAt, endedAt }` | 所有进程 append |
| `events.jsonl` | 每行一条事件：`{ ts, kind, ... }`，`kind` ∈ `subs-run` / `subs-candidate` / `task-queued` / `task-file` / `task-done`；单文件 5 MB 轮转，留一份 `.1`（ADR-0007） | 订阅进程 + 任务进程 append |
| `tags.json` | `{ tags: [...] }` 标签池（大模型只能从这里挑词） | server |
| `tag-pending.json` | `{ words: [{ word, count, at }] }` 池外新词，等人确认 | server |
| `ipwatch.json` | `{ updated, notes, groups: [{ name, risk, holder, event, source, ips[], keywords[] }] }` | 人手工维护 |
| `duplicates.json` | 见 §4.5 | grab + server |

- `tasks/*.jsonl` 是**审计日志**：永久保留，不裁剪；恢复队列只认 `queue.json` 的名单，
  别拿 jsonl 当队列真相（见 §3.2）。
- `events.jsonl` 是**给人看的运行日志**，不是审计：满 5 MB 就轮转，旧事件会被挤掉；
  事件流的用途是「刚才那一轮订阅搜了什么、这条候选为什么没进来、现在在下一个文件」。
- `lastResult` = `{ at, startedAt, searched, candidates, matched, stopped, jobs, from, cursor, error? }`：
  一轮搜了几次、出多少候选、入队多少、有没有失败。控制台直接显示这个，不重新算。

## 5. 判重规则

### 5.1 同站

按顺序判，命中即停：

1. **网址相同**（= 目录相同）→ 不是重复，是同一次抓取的重跑，直接覆盖更新。
2. **标题 + 作者相同** → **确认重复**，不下载，不建目录，写 `duplicates.json`（`scope: same`, `by: meta`）。

同站不比文件清单、不比 hash——网址和标题+作者已经够了。
判重键用 `platform + 站点 id`；MakerOnline `.cn`/`.com` 共用 `platform`，判重时再看 `site`。

### 5.2 跨站

1. **标题 + 作者相同** → 记为**疑似**，照常入库并下载（用户决定：先入库，不漏）。
2. 下载完成后，把这次抓到的**作者件** `sha256` 与疑似目标比：
   - 有交集 → 升级为**确认重复**：删掉本次目录，写 `duplicates.json`（`scope: cross`, `by: hash`）。
   - 无交集 → 保留，记 `duplicateOf`（`by: meta`），页面上标「疑似」。

**候选选择顺序**：先找同站命中，再找跨站命中；多条命中取最早入库的那条。

### 5.3 边界

- **只有字节完全相同才会撞同一个 hash**，所以 3mf 只会和 3mf 撞、stl 只会和 stl 撞，
  不需要额外判格式。
- `origin: 'other'` 的文件不参与比对（那不是原作者上传的）。
- 跨站作者名不同就漏判——**接受**（用户决定，不加身份键猜人）。
- 拿不到文件就没法确认，只能停在「疑似」——接受。
- 标题归一：NFKC + 去空白 + 小写；作者同理；**任一为空就不判重**（空标题/空作者会误杀一整批）。

## 6. 限速与配额

两道闸门，缺一不可：

| 闸门 | 值 | 位置 |
|---|---|---|
| 模型之间 | 60–120 秒随机（全局默认；站点可覆盖，见下） | 队列（**按站独立**，含图片与重试） |
| 模型内部每文件 | 5–10 秒随机 | 抓取子进程（文件、封面、盘图都算） |

- **闸门按站独立**：某站的间隔没到，只推迟这个站的任务，别的站照跑（同一时刻仍只有一条任务在跑）。
- **站点可覆盖**：包里的 `rate` 是站点固有默认，`data/site-config.json` 是用户覆盖，
  生效顺序 用户覆盖 > 包 `rate` > 全局默认。细则见 `docs/site-pack.md` §6。
- 60 秒是地板：`setGap`、环境变量、命令行参数、站点覆盖、`data/site-config.json` 都过同一个地板，
  调小等于关掉限速。
- **闸门是持久状态**：每个站的 `nextOkAt` 存 `data/queue.json`，重启后没走完的间隔继续等。
- **闸门对所有任务推进**，包括没下到文件的（登录失败也发过请求）。
- 搜索是另一条通道：**每站每分钟 4 次、两次之间至少 15 秒**。
- 订阅默认 8 小时一轮；一轮的入队量要小于这 8 小时能跑完的量（产能约 34/h）。
  超出配额不静默丢弃，记「已截断 N」并在控制台显示。
- 搜索也是产能：一轮 177 个词 × 4 站 ≈ 177 分钟，8 小时里占 37%。订阅每轮开始前
  按剩余时间算能跑几个词，跑不完的下轮接着跑，不许把一轮拖成十几个小时。

### 6.1 磁盘

- 入队前查 `library/` 所在分区的剩余空间，**低于 5 GB 就拒绝入队**并在控制台报警。
  单个 3mf 见过 173 MB，一个 48 文件的模型能吃掉几百 MB，写满磁盘比抓慢更糟。
- 磁盘用量按 `savedFiles[].bytes` 汇总，不递归 `stat`（628 个模型递归 stat 已经要 74 ms，
  再长下去控制台每次刷新都卡）。

### 6.2 订阅调度

订阅**只有三种，三选一**，用 `kind: 'keyword' | 'author' | 'feed'` 显式声明——不靠「用户列表空不空」推断，
推断式会在主页链接解析失败被清空时悄悄变成另一种订阅。

- **关键字订阅**：`keywords[]`（中英文逗号分割）+ `rules[]`（`站点 + 排序 + 筛选 + 前 N 条`，整条订阅共用
  一套规则）+ `matchModes[]`（`name` / `tag`，可多选，任一命中即算）+ 门槛条件。
- **作者订阅**：`users[]`（主页链接，站点从链接认）。**没有候选规则、没有匹配方式、
  没有门槛、没有排序**——订阅作者的意图就是「他发的我都要」。固定按站点默认序（五站实测都最新在前）。
- **榜单订阅**：`feeds[]`（`站点 + 榜单源 + 前 N 条`，可配多条）。**没有关键字、没有候选规则、
  没有匹配方式、没有门槛**——站方排出来的榜，上一条就是命中。

三种共用 `intervalHours / enabled / cursor / lastRunAt / lastResult`。

#### 榜单订阅

- 榜单源由站点包声明（`feeds: [{ key, label }]`，取数走 `feed(key, { page, pageSize })`，
  见 `docs/site-pack.md` §11.5），订阅里只存 `key`。**不让用户粘榜单网址**：站方换地址、
  改版都在包里改，订阅端不用动，也不会因为一个网址失效整条订阅废掉。
- **没声明榜单的站不出现**在表单的站点下拉里（`abilities.feeds` 为空）。
- 一条订阅可以配多条榜单（如「创想云本周值得打 + MakerWorld 精选」），每条独立跑、独立记增量。
- **不做提前停**：榜单顺序会变（人工滚动），撞到旧的不能说明后面没新的，所以每轮把前 N 条重扫一遍；
  已在库、已在队列的跳过，不重复入队（`subs.mjs` 的 `cursor` / `budgetMs` 照旧按轮算）。
- **前 N 条是硬上限**：`limit = 150` 就取 150 条，翻页凑出来的多余条数丢掉。
- 榜单没有候选台账：不落 `data/subs/<id>.candidates.json`（没有匹配与门槛可判），
  只把命中记进 `data/subs/<id>.hits.json`。

#### 筛选

- 只有关键字订阅的候选规则有，形如 `filters: { color: 'multi', badge: 'picked' }`，**每键单选**。
  键与值的全集见 `sites/contract.mjs` 的 `FILTERS`（`color`：多色/单色；`badge`：星标模型/
  独家/Maker 严选/会员模型/CyberBrick/耗材供应/可定制/参数化）。
- **只能要站点声明过的**：站点包用 `filters: { color: [...], badge: [...] }` 暴露本站支持的子集，
  公共层收到本站没声明的键或值就当没写（`docs/site-pack.md` §11.4）。控制台里没声明的键整个不出现
  ——给一个选了也不生效的下拉只会骗人。
- 筛选是「收紧搜回来哪些」，不改变匹配方式：筛完的结果仍然要过 `matchModes`。

#### 两个调度器

一轮拆成两段，各自排队，互不阻塞：

**订阅任务调度器**（会联网，吃搜索限速）
- 到期订阅展开成任务：关键字订阅 = `关键字 × 规则`，作者订阅 = 一个作者主页，榜单订阅 = 一条榜单。
- 每站一个运行器，先进先出，一次只跑一个任务。
- 按站点搜索限速执行（每站 4 次/分、间隔 ≥15 秒，站点可覆盖）。
- 产出候选，交给候选调度器。

**候选调度器**（纯本地，不联网、不占搜索配额、不受任何限速）
- 取一条候选，过下面四道闸，通过的进抓取队列。
- 一轮的搜索任务**全部跑完**才统一判定：跨站「标题+作者」合并要先攒齐所有来源，边搜边判
  会漏掉后到的站。判定是本地读盘，瞬时完成，等这一下不花时间。

为什么拆两段：搜索受站点限速，慢；判定是本地磁盘读，快。混在一起只会让限速空转。

#### 候选

候选 = 按规则搜出来、去过重的原始结果，**还没判定**。候选 ≠ 命中。

- 去重两级：先 `site:id`，再「归一化标题 + 作者」（复用 `dup.mjs` 的 `normText` / `metaKey`）。
  这与入库判重是两件事——入库判重看 `site:id` 与文件 hash。
- 同一模型在多个站搜到 → 合成一条候选，`sources[]` 记全部 `{site, url, rank, kw, rule}`；
  **入队取 MakerWorld 优先**，其余按名次。
- 落盘 `data/subs/<id>.candidates.json`，键 `site:id`，每条记
  `{key, sources, title, author, tags, decision, firstSeen, lastSeen}`。`decision` ∈
  `queued | no-match | threshold | in-library | in-queue`，这就是「为什么没进队列」的答案。
  30 天没再出现就清。
- **这个文件是台账，不是缓存**：每轮搜到的候选都重新判定，不沿用上次结论（本轮没搜到的老条目
  保持上次的 `decision`，等它再被搜到才重判）。判定是本地读盘（毫秒级），
  省它没意义；沿用反而有害——你手动删了库里的模型，它还会被记成 `in-library` 永远不下。
- **前 N 条是硬上限**：`limit = 150` 就取 150 条，翻到第 8 页（160 条）多出来的 10 条要丢掉，
  不许凑成整页。
- **门槛按主来源那条的数值判**：跨站合并后 `likes / downloads / picked` 取 `sources` 里
  MakerWorld 那条（没有就取名次最好的那条）。

#### 匹配方式

- `name`：归一化标题**包含来源词**。来源词 = 这条候选被哪个关键字搜出来的（`sources[].kw`），
  不是「订阅里任一词」——用任一词会跨词误伤。
- `tag`：**只用搜索结果自带的标签**，不打开详情页。实测（2026-11-02）：MakerWorld 结果带
  `tags[]`（前 20 条 tag 精确含关键词 20/20）；Snapmaker 结果没有 `tags`，只有 `translatedTags`
  （中文译名，如「可爱/摆件/关节可动的」）——**算**，当加分项用（命中就放行，译名对不上也不算失败，
  反正不额外花请求）；创想云结果不带标签（只带 `categoryName`）；MakerOnline 结果项里没有 tags 字段。
  → **创想云与 MakerOnline 不支持 tag 匹配**。`matchModes` 是订阅级开关，没法只灰掉某一站的
  勾选框，所以这两站的规则在表单里**行尾标注**「该站搜索结果不带标签」；勾了 `tag` 的订阅如果含
  这两站的规则，那条规则只用 `name` 判，不算失败。Snapmaker 的 `translatedTags` 要由
  站点包归到 `tags` 字段（`sites/snapmaker.mjs` 现在读 `raw.tags` 恒空）——这是站点包契约的事，
  不在订阅里打补丁。反证：创想云按下载量排序
  第 1 页 20 条里名字命中 8 条，抽查未命中的 8 条打开详情页，tag 含关键词的 **0 条**——花钱开详情页
  换 0 命中，不做。
- `ai`：不做，字段不存。

#### 入队前四道闸（候选调度器里，纯本地）

1. **库里有没有**：直接读 `library/<site>-<id>/model.json`，`savedFiles` 非空就算有（STL 或 3MF
   都算）。**不建索引、不批量重建**——按 id 找那一个目录是 O(1)，且永远最新。没下到文件的
   （`noFiles`）不算入库，空记录不许拦住重抓。
2. **下载队列里有没有**：url 处于 `queued / fetching / parsing / downloading` 任一阶段 → 丢。
3. **门槛**（只关键字订阅）：`minLikes` / `minDownloads` / `pickedOnly`。
4. **名字匹配**（只关键字订阅）。

**没有「每轮名额」，也没有「每日入队上限」**：候选调度器先进先出，没有全局排序、没有按站分配名额，
积压就慢慢下。排队闸门（60–120 秒/模型）才是真正的节流。

**手动入队不受订阅排队影响**：手动加的链接与「插队」按钮都走 `lane.unshift` + 轮转指针前移，
下一个就跑它（闸门照旧）。订阅塞进来的几千个排在后面，不会挡住手动抓取。

#### 作者订阅的增量

五站作者页实测都是**最新在前**，且都不需要传排序参数（2026-11-02，MakeRoad 2026-11-03）：创想云 `createTime` 降序、
MakerWorld `createTime` 降序、Snapmaker `published_at` 降序、MakerOnline `mold_id` 降序、
MakeRoad `editTime` 降序（用户模型接口不吃 `sort` 参数，传了也忽略）。

- 第一次跑：从第 1 页翻到底，全量入队。
- 之后每次：从最新往旧扫，**连续 20 条（一页）都已在库里或在下载队列里**就停。
  为什么不是「第一条就停」：作者可能删了重传，或者某条之前抓失败——一条旧的后面还藏着新的。
- **首次全量必须能断点续翻**：作者有 500 个模型时一轮预算翻不完。每个作者主页记一个页码游标
  （`authorCursor: { "site:id": { page, done } }`），被打断就从那一页接着翻；翻到底才置
  `done: true`，从此才启用「连续 20 条就停」。否则第二轮从第 1 页重扫、立刻撞上 20 条旧模型
  就停，第 30 页以后的永远下不到。

作者订阅**不经过候选调度器**：它是「他发的我都要」，没有候选、没有匹配、没有门槛，
搜到一条过完库/队列两道闸就直接进抓取队列，所以也不写 `candidates.json`
（控制台里作者订阅没有候选清单，这是对的）。

关键字订阅**不做增量**：搜索结果按相关性/下载量排，与时间无关，做不到「撞到旧的停」。

作者订阅**目前不提供排序选项**，固定站点默认（最新），否则增量不成立。记录在案：MakerWorld 作者页
支持 `?orderBy=downloadCount` / `likeCount`，将来要开排序先用它；其余三站作者页没有排序控件，
接口传参也无效。

#### 失败、预算、断点

- 「搜索失败」与「搜到 0 条」必须分开：前者记 `lastResult.error`，后者才是翻页到底。
- 拿不到总数写 `null`，不许写 `0`（`0` 会被当成「翻页到底」提前收工）。
- 一轮有时间预算 `intervalHours × 0.6`（地板 60 秒）。四站并行跑，耗时按**单站最多任务数 × 15 秒**
  估（不是「词 × 站」相加）。跑不完记 `cursor` = 第一个没跑完的任务下标，下轮接着跑，跑到头才
  归零；词表或规则一改就重置，否则序号错位。
- 搜索失败只影响那一个任务：已经搜到的页照常进候选，不整轮作废。
- 订阅之间**串行**（一条跑完再跑下一条），只有同一订阅内部的站是并行的。
- `lastResult` = `{ at, startedAt, searched, candidates, matched, stopped, jobs, from, cursor, error? }`。
- 订阅的入队**不受暂停影响**（暂停只停抓取，不停止订阅发现新模型），入队后的任务照样等闸门。
- 磁盘 <5 GB 不排队。

#### 迁移

老订阅没有 `rules`：按 `sites[]` 逐站生成 `{site, sort: 原 sort, limit: pageLimit × 20}`，
`kind` 定为 `keyword`，迁移后删掉 `sites / sort / pageLimit`。`ipwatch.mjs` 同步改成写 `rules`。

### 6.3 匿名优先（接口级）

ADR-0003 的机制，按**接口**而不是按站点：

- 每个请求先匿名（不带 cookie，也不碰浏览器）；失败退避 2 秒再匿名一次；还失败才带登录；
  带登录还失败就强制刷新登录态再试一次；仍失败本轮结束。
- 结果记 `data/auth-needs.json`（600）：`needsLogin: true` 的接口**下次直接带登录**，
  匿名能成的接口记 `needsLogin: false`，之后一直匿名。
- 连续 3 轮带登录都失败 → 标 `broken`，不再白试，任务报「多半是站点改了」。
- 站点包可以声明 `loginOnly: [路径]`（按设计就要登录的接口，比如创想云 `memberDownload`），
  抓取时直接记进表里，不浪费两次必然失败的匿名请求。
- 这个文件只存「站点 + 接口路径 + 布尔 + 计数」，**不含任何凭据**，也不进日志。

### 6.4 IP 词表订阅

`ipwatch.mjs` 把一份人工维护的高风控 IP 词表（`data/ipwatch.json`）同步成订阅：

- **只走 server 的订阅接口**，不自己写 `subs.json`（§8 单写者）。
- 幂等：按订阅名 `IP·<组名>` 认领，已有的就更新，没有的新建；重复跑不许产生重复订阅。
- **词表里删掉的组，对应订阅要停用**（`enabled:false`），不许留着永久跑——
  删了词却还在抓，是最难发现的那种浪费。
- 风险分档决定轮询间隔（风险 5 → 4 小时，风险 2 → 24 小时），非法值按最保守的 24 小时算。
- 单组关键字为空、`risk` 不是 1–5 的整数，一律报错退出，不许静默跳过（跳过等于这组白写）。
- 词表跑完写一份 `data/ipwatch.md` 给人看，不算数据契约。

## 7. 登录态

- 三态：`logged-in` / `logged-out` / `unknown`。**连不上浏览器就是 `unknown`**，
  界面上显示「无法检测」，不许说「未登录」（AGENTS.md 不可省）。
  探测抛错也归 `unknown`，不新增第四态。
- 只从本机常驻 Chromium 进程内现取（`context.cookies()`），不落盘、不打印、不进日志。
- 探测请求必须有超时（15 秒）；任一站点挂住不许把整个 `/api/console/login` 拖死。
- MakerWorld 的搜索与详情走 `api.bambulab.cn` 公开 API（匿名、纯 node），不依赖登录态、也不占浏览器；
  浏览器只剩四件事：f3mf 兜底、登录态探测（api 域无公开端点）、作者主页列表（handle→uid 无公开端点）、
  分类树（公开 API 只有一级、没有二级）。
- MakerWorld 的文件先走 CDN 裸链（3mf 在 CDN 上是公开文件，匿名可下）：未登录也能拿到这部分。
  反推不出裸链的配置（没生成过 3D 预览）才回落 f3mf，那时未登录记 `noFiles: "login"`；
  用户登录后统一补抓（控制台的「待补抓」）。
- MakerWorld 的 f3mf 在「已登录」时仍会撞人机验证（实测 418 + geetest）：这是 `captcha`，
  **不是** `login`，只发一次请求就放弃，不逐个打印配置重试；已拿到的 CDN 文件照常入库，
  日志点名是哪几个配置缺。
- MakerOnline 不再撞验证码：`POST /api/file/download` 带 `Platform: ios`（站点给 App 的通道）
  直接回签名直链，3mf / STL / 文档同一接口（`file_type` 2 / 1 / 3）；头值必须精确是 `ios`，
  `android` / `web` / 大写 `iOS` 都被拒（回 `{"code":1,"message":"The system is busy."}`）。
- MakerOnline `.cn` 与 `.com` 的登录态互不相干，**cookie 按域取、不许合并进同一个请求头**。
  同一个 `platform` 下两个域各自探测、各自报状态。
- **缓存与刷新**：登录态缓存 60 秒、cookie 缓存 300 秒——工作台每次刷新都打一遍五个探测
  会把浏览器和站点都拖慢。但用户点「重新检测」时必须**强制刷新**（跳过两个缓存），
  否则刚登录完要等一分钟才看见变化。
- 缓存不能掩盖 `unknown`：连不上浏览器时缓存里存的也必须是 `unknown`，不许留上次的
  `logged-in`（那会让人以为还能下文件，实际一个都下不到）。

## 8. 并发与数据归属

**一个文件只有一个写者**：

| 文件 | 唯一写者 | 其他进程 |
|---|---|---|
| `library/*/model.json` | `grab.mjs`（打标签是唯一例外：只增补 `llmTags`） | 只读 |
| `data/queue.json` | 队列所在进程（单写者，原子写） | 只读 |
| `data/subs.json` | server（`ipwatch` 改走 API） | 只读 |
| `data/duplicates.json` | `grab.mjs` 子进程 + server（读改写要在同一把锁里） | 只读 |
| `data/tasks/*.jsonl` | 所有进程 append；**行内不记归属**，归属由 `queue.json` 的排队 id 决定 | 只读 |
| `data/preview/<dir>/` | server（按需生成，可随时删） | 只读 |

- 批抓（`bulk.mjs`）**不再自带队列**，一律 `POST /api/grab` 入队，共用同一份闸门与去重。
- `ipwatch.mjs` 不再直接 `import subs.mjs` 写盘，改走 server 的订阅接口。
- 进程内缓存（`dup.index`、`subs.load`）必须能失效：订阅每轮开始 `load(true)` / `index(true)`，
  否则别的进程新写的内容永远看不见，而且下一次 `persist()` 会把它整份覆盖掉。

### 8.1 浏览器通道

只有一个入口连 CDP 9223，规则不多但都不能省：

- **单飞**：同一时刻只有一个连接在做「取页」。并发连会把握手拖到超时（实测单客户端 20 秒，
  5 个并发全部超时），然后标签泄漏、然后更慢。做法是 `channel.mjs` 里一条显式闸门
  （全局并发 1，站间轮转），所有要浏览器的调用都排队进去。
  闸门是**进程内**的；抓取子进程由任务队列串行（同一时刻只有一个），所以跨进程最多只多一个客户端。
- **每个 CDP 调用都有超时**：连 20 秒、取 cookie 15 秒、开页 20 秒、页内执行 60 秒。
  以前只有连接有超时，页面 `goto` 没有，卡住就永远卡住。
- **断线自愈**：连接断了下次自动重连，不要让人手动重启服务。
- **关标签页时先确认还有别的页**：要关的是最后一个标签页时，**先开一个空白页再关**，
  否则会把用户的 Chromium 整个关掉（连带下次抓取全失败）。
- **子进程退出前必须关掉自己开的页**（3 秒上限），异常路径也要关——
  实测漏关 11 小时攒了 15 个残留标签页，把 connect 拖到 30 秒。
- cookie 从 `context.cookies()` 现取，缓存 300 秒；不落盘、不打印、不进日志。

## 9. 接口

### 9.1 列表与详情

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/models` | 只发卡片字段，60 秒缓存；690 个模型约 500 KB |
| GET | `/api/model?dir=` | 单个模型完整数据（详情页用），比列表多 `description/docs/profiles/activeProfileId/files/siteOnlyFiles/images/localImages` 与 `savedFiles[].path/sha256/origin` |

**卡片字段**（`/api/models` 每条）：`dir` `id` `platform` `site` `title` `author` `category` `cat`
`tags` `autoTags` `llmTags` `translated` `fetchedAt` `stats` `cover` `profileCount` `print`
（只含 `timeSec/timeText/weightG/plates`）`savedFiles`（只含 `name/kind/exists`）`noFiles` `picked` `sourceUrl`

  `exists` 每次按磁盘实际情况标。

### 9.2 写入

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/grab` | 入队一个网址，**立刻返回 202 + taskId，不等抓完** |
| POST | `/api/files` | 补抓某个模型缺的文件，同样立刻返回 |
| DELETE | `/api/model` | 删一个模型目录（要 `dir`），同时清 `duplicates.json` |
| GET | `/api/inspect` | 3mf/stl 预览（派生数据，缓存写 `data/preview/`） |
| GET/POST | `/api/console/*` | 控制台：工作台、站点包（`sites` 聚合卡 + `checkin` 签到 + `site-config` 自定义限速/搜索频率/自动签到）、任务（列表/重试/插队/停止/暂停/继续）、订阅（增删改/立即跑/命中记录）、重复标记、打标签（单条/全部/待确认新词）、事件时间轴 |

- 所有写接口都要先校验参数，再动文件。
- **删模型是「我不想要它」**：目录、`data/preview/` 里的派生数据、`duplicates.json` 里指向它的
  条目一起清。删掉之后订阅**会**重新抓到它——这是预期（入队前的库检查只看库里有没有），
  要永久排除得靠订阅自己的关键字，不另做黑名单。
- 路径参数一律认真实路径（`realpath`），软链接指到库外的一律拒绝。
- 请求解析失败返回 400，服务端异常返回 500，**不许因为一个坏请求把进程弄死**。
- 前端等结果就轮询任务状态，不靠长连接挂着。

### 9.3 前端

零构建，两个页面：库（`/`）与控制台（`/console`）。行为契约：

- **详情用 hash 路由**（`#m=<dir>`）：刷新、分享、后退都要能回到同一个模型。
  筛选与排序也进 hash（`#q=…&site=…`），否则刷新就丢。
- 详情数据按需拉 `/api/model?dir=`，列表只带卡片字段。
- 抓取/补抓**立刻显示排队状态并轮询**，不许把按钮卡在「抓取中…」等整次入库
  （一次入库含 60–120 秒闸门，等下来是几分钟）。
- 失败要显示人话（§10 的错误表），并保留「再试一次」的入口。
- 打印配置可以按机型筛（能力位来自 `profiles[].machines`），没有机型信息的站点不显示筛选器。

**详情页右栏**（从上到下）：标题卡 → 打印配置卡 → 打印盘面板 → 同模型链接 →
`原页面 ↗ / 重新抓取 / 删除` 一行。**没有「文件」栏**——文件列表、文件预览、逐文件下载全部去掉，
配置卡底部那条按钮已经覆盖了「拿到能打印的东西」这件事。

- **原件行**：只有**本地没有 3mf** 的模型才出现（一行「原件 · N · 文件名」）。
  有 3mf 就够打印了，原件不再展示；文件仍在盘上，只是没有入口。
- **作者徽标**：配置行在机型/耗时那一行前显示小图标 + 绿色「作者」，**仅当配置作者 = 模型作者**
  （§4.2 作者身份表）。他人配置不标；站点没有这个字段就不显示，不猜。
- **点哪条配置，下面的打印盘就换哪条**：`profiles[].id` 一律按字符串比较。站点给了 `plateList`
  就直接用；没给（创想云）就在点选时解析本地对应 3mf（`/api/inspect`，对应关系见 §4.2），
  没有本地 3mf 就不显示盘面板——不显示假数据。
- **配置卡底部一条按钮**，作用于当前选中的配置：左「发送到打印机」（功能待做：灰按钮 +
  点了说一句还没做），右「下载 3MF」——有本地 3mf 就下载，没有就变「去站点下载 ↗」。
  没有打印配置的模型不出现这条按钮。

| 站点包 | 每站一张卡片，五行：①站名 + 红绿灯登录态 + 账号名 ②积分 · 今日签到得分 · 连签天数 · 自动签到开关（未签才给签到按钮）③库内 N 个 · 最近 1 天抓 M 个 · 待补抓 ④近 7 天入库柱状图（只数带 3mf 的）⑤下载限速 + 搜索限速（改完即存，留空=跟随全局）。**不展示**额度、重置时间、额度走势、打码——本站没有这些概念（`docs/site-pack.md` §4、§6） |

- 轮询只在当前分页开着时跑；整表内容没变就不重画（否则 5 秒一次吞掉输入焦点）。
- 任务页的按钮在任务进行中要禁用，避免连点重复 POST。

### 9.5 两种搜索，别混

| | 库内搜索 | 站点搜索 |
|---|---|---|
| 用在哪 | 列表页搜索框、筛选、排序 | 订阅发现新模型 |
| 数据源 | 已经在库里的卡片 | 四站各自的搜索接口 |
| 速率 | 不限（纯本地） | 每站每分钟 4 次、两次之间 ≥ 15 秒 |
| 失败 | 不会失败 | 必须让调用方知道（不许 `catch` 成空数组） |

- 列表页的搜索**不许**去请求站点：每敲一个字打四次站点接口，等于自己把自己封掉。
- 站点搜索只服务订阅；结果归一化成同一形状（`url/title/author/site/likes/downloads`）再入队。
- 「搜索失败」与「搜到 0 条」必须分开：前者记 `lastResult.error`，后者才是翻页到底。
- **排序只能要站点声明过的**：每个站点包用 `searchOptions.sorts` 暴露支持的排序键与页大小，
  公共层收到本站没有的键就回落该站默认序（`docs/site-pack.md` §11.2），不静默照传。
- **筛选也只能要站点声明过的**：站点包用 `filters` 暴露支持的键与值（§11.4），本站没声明的
  键/值一律当没写——传下去只会在站点端静默失效，用户还以为筛了。
- **总数拿不到写 `null`，不许写 `0`**：`0` 会被订阅当成「翻页到底」，把这一轮提前结束。

## 10. 任务状态

```
queued → fetching → parsing → downloading → done
                                          ↘ duplicate（判重命中，算成功）
                                          ↘ failed（重试用尽 / 超时 / 站点不给）
                                          ↘ stopped（人点的停止，终态，不计失败）
                                          ↘ interrupted（被重启打断，会续跑）
```

五个终态：`done` `duplicate` `stopped` 是成功侧（`stopped` 单独记，不算成功也不算失败），
`failed` 是失败侧，`interrupted` 不是终态（下次启动续跑）。

- 本任务内最多试 3 次；跨轮次累计失败 3 次才置 `failed`。
- `duplicate` 是**成功**的一种，不是失败，不重试。
- **人点的停止是终态**：记 `stopped` 原因，不重试、不计入失败统计（不算「重试用尽」）。
- 失败要记人话（比如「浏览器没连上」「要登录」「超时 30 分钟」），不许记
  `Node.js v20.19.2`、`退出码 0` 这种。
- 成功退出但没走到 `done`（例如中途 `exit(0)`）要单独归类，不许当成「退出码 0 的失败」。

### 10.1 失败原因表

错误串是给人和给控制台看的，按这七类写，不许把堆栈当错误串：

| 类别 | 触发 | 用户该做什么 | 重试有意义吗 |
|---|---|---|---|
| `unknown-site` | 网址不在站点包白名单 | 换个网址 | 没有（终态） |
| `parse` | 站点结构变了，解析点没拿到数据 | 等修解析器 | 没有（重试还是同样的页面） |
| `login` | 站点要登录才给文件 | 登录后点补抓 | 登录后才有 |
| `captcha` | 站点要人机验证（MakerWorld：418 + geetest） | 浏览器里过一次验证再补抓 | 过验证后才有 |
| `browser` | 连不上 CDP 9223 | 开 Chromium | 连上之后才有 |
| `timeout` | 30 分钟没跑完 | 看是不是站点卡了 | 有一次 |
| `network` | 连接被拒/重置/5xx | 等一会 | 有 |
| `disk` | 磁盘剩余不足 | 清理磁盘 | 清理之后才有 |

- 「没有意义的重试」要在入队时就判掉（`unknown-site`），别排三次再失败。
- `parse` 与 `login` 是最常见的两种，控制台要分开计数（「待补抓」按原因分四行显示）。

## 11. 验收标准

一条一条都能跑：

1. `curl --path-as-is '/%E0%A4%A'` → 返回 500，**服务还活着**。
2. `library/evil.json` 是软链指向 `/etc/passwd` → `/library/evil.json` 返回 403。
3. `?id=../tasks/secret` 读订阅命中 → 返回空数组。
4. `POST /api/grab {"url":"http://127.0.0.1:8851/api/models?u=https://www.crealitycloud.cn/model-detail/<24hex>"}`
   → 拒绝入队（host 不是站点），服务端不去请求自己。
5. 同站同标题同作者的两个网址 → 第二个判 `duplicate`，不下载、不留目录。
6. 同站标题不同 → 不判重（实测过一对「大肌霸皮卡丘」，误删过 61 MB）。
7. 跨站同标题同作者、文件不同 → 入库并标「疑似」，不删。
8. 跨站同标题同作者、作者件 hash 相同 → 删本次目录，`duplicates.json` 有记录且 `scope:"cross"`。
9. `origin: 'other'` 的文件参与比对 → 不算命中。
10. 一个 48 文件的模型 → 相邻两次下载间隔 ≥ 5 秒（图片也算）。
11. 两个模型之间 → 间隔 ≥ 60 秒，**包括上一个任务没下到文件的**。
12. 重启服务 → 暂停状态保持；`nextOkAt` 没走完不许开跑。
13. 点「暂停抓取」→ `data/queue.json` 写 `paused:true`；重启服务 → 仍是暂停。
14. MakerWorld 未登录抓一个模型 → CDN 裸链能反推出来的文件照下；一个都反推不出来时
    `noFiles: "login"`，任务 `done` 不是 `failed`。撞人机验证时记 `captcha`，f3mf 只发一次请求。
15. 抓取子进程被 SIGTERM / 卡住 30 分钟 → 关掉自己开的标签页再退出，任务记「超时」。
16. 同一网址连点两次「抓取」→ 队列里只有一条。
17. `POST /api/grab` → 1 秒内返回 202 + taskId。
18. `/api/models` 响应 < 1 MB（700+ 模型），且 60 秒内第二次请求走缓存。
19. 抓取中 `DELETE /api/model` → `duplicates.json` 里指向它的条目一起消失。
20. 暂停中点「抓这个」→ 只这一个开跑，队列里其它任务仍停；它跑完仍是暂停状态。
21. 抓取卡住 30 分钟 → 子进程先收到 `SIGTERM`（日志有「收到停止信号」），标签页被关掉，
   5 秒后还没退才被 `SIGKILL`；任务记 `timeout` 而不是空错误。
22. `data/queue.json` 里**只有** `paused`/`nextOkAt`/排队 id，`grep -c '"url"' data/queue.json` → 0。
23. 24 小时内成功过的网址再点抓取 → 不入队，返回既有任务；**失败过的再点 → 真的重新入队**。
24. 订阅到点开跑时再点「立即跑」→ 返回「正在跑」，不并发跑第二轮。
25. 打标签连点两次「全部」→ 第二次返回「正在跑」，不重复花钱。
26. 浏览器里只剩一个标签页时抓完 → 关页前先开空白页，Chromium 仍连着（没被关掉）。
27. 在库列表搜索框打字 → 抓包看不到任何外网请求（本地过滤）。
28. 控制台六个分页逐一点开都能出内容，控制台无 JS 报错。
29. `node ipwatch.mjs` 连跑两次 → 订阅数量不变（幂等），词表里删掉的组对应订阅变成停用。
30. `node --test test.mjs` 全绿。
31. 一条关键字订阅配两条规则（MakerWorld 相关性前 100 + Snapmaker 下载量前 50）→ 同一关键字搜 2 次，
    候选清单里同一模型只出现一条，`sources` 里有两条记录（各自带名次）。
32. 候选判定时库里有这个模型但 `savedFiles` 为空 → 不算入库，照样入队。
33. 库里有这个模型且有 STL（没有 3mf）→ 候选 `decision` 记 `in-library`，不入队。
34. 作者订阅第二次跑：该作者最近 20 个模型都已在库 → 只翻一页就停（不再往更旧翻）。
35. 关键字订阅勾了 tag 匹配、规则里有创想云 → 控制台里创想云的 tag 选项是灰的，说明写「该站搜索结果不带标签」。
36. 候选调度器在跑时抓包 → 看不到任何外网请求（纯本地判定）。
37. 老订阅（没有 `rules`）→ 迁移后 `kind` 全是 `keyword`，每条按 `sites` 生成了规则，`sites/sort/pageLimit` 三个字段消失。
38. 规则 `limit = 150` → 候选不超过 150 条（第 8 页多出来的 10 条被丢掉，不凑整页）。
39. 作者订阅首次全量被时间预算打断 → 下一轮从断的页码接着翻，不回到第 1 页重扫。
40. 手动删掉库里一个已入库的模型 → 下一轮同一模型重新入队（候选台账不沿用旧结论）。
41. 同一个关键字配两条都指向 MakerWorld 的规则（相关性 / 下载量）→ 候选去重成一条，两次搜索都真的发生了。

## 12. 测试口径

- **只测外部行为**：函数返回什么、文件写出来长什么样、HTTP 回什么状态码；不测内部函数调用次数。
- **一个缝**：所有需要落盘的东西都从 `MARKLAB_ROOT` 环境变量解析根目录（默认仓库根）。
  测试用 `mkdtemp` 造一个临时根，把 `library/` `data/` 放进去，整应用指过去——
  不新开第二套"测试模式"，不在生产代码里留 `if (test)`。
- 纯函数直接 import（`lib.mjs` / `dup.mjs` / `stats.mjs` 的纯逻辑）——已有先例。
- 服务端用真的 `node server.mjs`，随机端口 + 临时根，`fetch` 打过去验状态码与 JSON 形状——已有先例（本轮实测就是这么做的）。
- 队列/限速测试**不许改 `MIN_GAP` 绕过 60 秒地板**——地板是产品规则，测试绕过它等于没测。
  验顺序用直接调内部的缝（`_testFinish(id)` 之类），验闸门就验「设了、持久化了、重启读回了」，
  不 sleep 真实 60 秒。
- 判重已经支持注入库目录（`dup.index(force, libDir)`），保持这个形状。

## 14. 遗留决策（还没定）

- `data/` 什么时候该上 sqlite（现在文件够用，过 5000 个模型再说）。
- 服务是否改绑 `127.0.0.1`（用户当前决定：**不改**；代价是上面第 1、2 条的入口在局域网内可用）。
- MakerOnline 若必须放弃 `__NUXT__` 求值，是换接口还是退到「只抓元数据、不抓文件」。
- **要不要把匿名 HTTP 收成一个池**（原 `docs/architecture.md` §4.1 的 `net.mjs`）：统一超时、
  状态码检查、最多 3 次退避重试、`Content-Length` 校验、流式落盘同时算 sha256。现在这些散在
  `grab.mjs` 与各站点包里各写一遍；没做是因为四个站的文件下载路径差别大，先按站各自实现更省事。
- ~~要不要事件流~~ **已定**：要，但收成一份 `data/events.jsonl`（不是每子系统一个文件），
  见 §4.7 与 ADR-0007。
- **要不要把原子写单独拆成 `store.mjs`**（原 §6）：现在 `lib.mjs` 的 `writeJson` 已经是
  tmp + rename，只是没 `fsync`、临时名不带 pid（两个进程同时写会撞）。等真出现并发写再拆。
