# 四站搜索排序参数（浏览器实测）

2026-10-31 实测。**方法**：在真浏览器里打开各站搜索页（`channel.mjs` 连本机 CDP），
点搜索框输入关键字回车，再在页面的排序控件上逐个点，抓页面自己发出的那个请求——
读出来的参数值就是站点认的值，不用猜。

抓法：进页面前给 `window.fetch` / `XMLHttpRequest` 装一个记录器，点一次排序读一次新请求的 body / query。

## 一张表（UI 上的名字 → 真正发出去的参数）

| 站点 | UI 排序项 → 参数值 |
|---|---|
| 创想云 | 综合趋势→**不传** · 最新上传→`sortType=3` · 浏览数→`9` · 点赞数→`1` · 收藏数→`2` · 下载数→`7` · 打印数→`6` · 助力数→`12` |
| MakerWorld | 相关性→`orderBy=score` · 热门→`hotScore` · 助力数→`boosts` · 最新→`newUploads` · 下载量→`downloadCount` · 点赞量→`likeCount` |
| Snapmaker | 热门→**不传** · 最新→`sort=latest` · 下载量→`downloads` · 点赞量→`like` · 收藏量→`collects` |
| MakerOnline | 相关性→`order=""` · 最多下载→`order=download_num_desc` · 最新上传→`order=submit_at_desc` · 最多点赞→`order=like_num_desc` |

## 创想云（`sortType`，数字）

POST `/api/cxy/smart_search/v1/model`，body 里 `sortType`。UI 上没有的值一律等于默认（综合序）。

| 值 | UI 名字 | 实测对哪个字段单调（20 条一页） |
|--:|---|---|
| 不传 | 综合趋势 | 四个指标都不单调（站点综合算法） |
| `3` | 最新上传 | 发布时间不升 19/19 |
| `9` | 浏览数 | `pv` 不升 20/20，前 5 = 54445 / 52893 / 50447 / 47180 / 46895 |
| `1` | 点赞数 | `likeCount` 不升 18/19 |
| `2` | 收藏数 | `collectionCount` 不升 18/19 |
| `7` | 下载数 | `downloadCount` 不升 18/19，前 4 = 11108 / 4484 / 4327 / 4292；第 1 页末 1278 → 第 2 页首 1274，翻页衔接正常 |
| `6` | 打印数 | `printCountTotal` 不升 18/19，前 5 = 2144 / 1146 / 811 / 803 / 602 |
| `12` | 助力数 | 对 `shareCount` / `promoCount` 都不单调（前 5 = 301 / 68 / 160 / 15 / 6），助力字段不在搜索结果里，**别用** |
| `5` | 无 | 会换序，UI 里没有对应项，语义未确认 |

坑：`sortType: 10` 曾被当成「下载量」写进适配器，实测 10 与不传**逐条同序**——创想云的 `sort=downloads`
一直空转，2026-10-31 改成 7 才真的按下载量取数。

## MakerWorld（`orderBy`，字符串）

GET `/api/v1/search-service/select/design2?orderBy=`，必须走页面内 fetch（直连被 Cloudflare 挡，403）。

| 值 | UI 名字 | 证据 |
|---|---|---|
| `score` | 相关性 | 默认；四个指标都不单调 |
| `hotScore` | 热门 | 会换序，不单调（站点热度算法） |
| `boosts` | 助力数 | 会换序；助力数不在列表字段里，只认 UI 这个值 |
| `newUploads` | 最新 | 发布时间不升 19/19，前 3 条下载 0 |
| `downloadCount` | 下载量 | 下载不升 19/19，前 3 = 7475 / 6038 / 5651；第 1 页末 2449 → 第 2 页首 2129，翻页衔接正常 |
| `likeCount` | 点赞量 | 点赞不升 19/19 |
| 其他乱填 | 无 | 与 `score` 逐条同序（静默回落，不报错） |

## Snapmaker（`sort`）

GET `api-models.snapmaker.cn/api/model/list?sort=`。

| 值 | UI 名字 | 证据（无关键字全站列表；查 `pikachu` 时计数全是 0，看不出语义） |
|---|---|---|
| 不传 | 热门 | 默认 |
| `latest` | 最新 | 发布时间不升 19/19 |
| `downloads` | 下载量 | 下载不升 19/19，前 5 = 95 / 52 / 32 / 32 / 28 |
| `like` | 点赞量 | 点赞不升 19/19，前 3 = 15 / 13 / 10 |
| `collects` | 收藏量 | 收藏不升 19/19，前 3 = 17 / 14 / 13 |
| `likes`（复数）| 无 | 与不传逐条同序（静默忽略） |

坑：这站没有相关性排序，默认序是站点「热门」；点赞参数是**单数** `like`，写成 `likes` 会被静默忽略。

## MakerOnline（`order`）

POST `/api/search/model`，body 里 `order`。

| 值 | UI 名字 | 备注 |
|---|---|---|
| `""` | 相关性 | 默认 |
| `download_num_desc` | 最多下载 | 换序明显：首 3 下载数 248 / 232 / 211，而默认序里前 20 条下载数只有个位数 |
| `submit_at_desc` | 最新上传 | 首 3 下载 0 |
| `like_num_desc` | 最多点赞 | — |

坑：早前以为「这站没有排序参数」，是因为试的是 `order=download` 这类错误值——正确值是 `*_num_desc` 形式。

**带关键字也认 `order`**（2026-11-02 实测，`.cn` 与 `.com` 都一样）：以前包里的 `order: keyword ? '' : ...` 会把调用方的排序静默丢掉，现已去掉。
响应里**没有发布时间字段**，所以本地按 `publishedAt` 重排对这站无效（要最新就直接用站点的 `submit_at_desc`）。

## 关键词匹配松紧（跟排序是两件事）

同一个关键字，各站「标题里到底有没有这个词」的比例差很多，这决定了排序再好也躲不掉的错误命中：

| 站点 | 排序 | 第 1 页 20 条标题命中「皮卡丘/pikachu」 |
|---|---|---|
| 创想云 | `sortType=7` 下载 | 8/20 |
| 创想云 | `sortType=1` 点赞 | 7/20 |
| 创想云 | `sortType=3` 最新 | 5/20（第一条是「七龙珠--布玛」） |
| MakerWorld | `score` 相关性 | 20/20（前 100 条 97 条命中） |
| MakerOnline | 默认 | 20/20 |
| Snapmaker | 任意 | 只匹配标题中文（「皮卡丘」6 条，「pikachu」45 条） |

**创想云的关键词匹配是按标签/分类松匹配的**：不管哪个排序，标题命中率都只有 5–8/20（宝可梦同族、甚至七龙珠、小马宝莉）。
所以订阅要压错误命中，创想云这站得靠标题二次过滤，换排序救不回来。

## 怎么复测

最快是用浏览器点一遍（抓页面自己发的请求）：

```js
// 存成 /tmp/x.mjs，node /tmp/x.mjs
import * as ch from '/home/gly/marklab/channel.mjs';
const p = await ch.page('makeronline');                       // 站点 key 见 channel.mjs 的 DOMAINS
await p.goto('<搜索页 URL>', { waitUntil: 'domcontentloaded' });
await new Promise((r) => setTimeout(r, 4000));
await p.evaluate(() => {                                       // 装请求记录器
  window.__req = [];
  const of = window.fetch;
  window.fetch = function (u, o) { window.__req.push({ u: String(u), b: String((o && o.body) || '') }); return of.apply(this, arguments); };
});
// 再点排序项，读 window.__req 里新增的那条
```

纯接口复测（能直连的站）：

```sh
# 创想云：看第 1 页下载数是否单调不升
curl -s 'https://www.crealitycloud.cn/api/cxy/smart_search/v1/model' -H 'content-type: application/json' \
  -d '{"page":1,"pageSize":20,"keyword":"皮卡丘","sortType":7,"printers":[],"promoType":0,"isVip":0,"trendType":1,"multiMark":0}'
# Snapmaker：sort 换成 latest / downloads / like / collects 各打一次
curl -s 'https://api-models.snapmaker.cn/api/model/list?page=1&pageSize=20&sort=downloads'
```
