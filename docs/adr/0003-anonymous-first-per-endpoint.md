# 0003 · 匿名优先，按接口记「需登录」，不机械撞墙

- 状态：已采纳（2026-10-29）

## 背景

用户的要求原话是：「所有抓取任务首先尝试不带登录状态抓取，不行再带登录状态抓取」，
动机是**保护账号不被封**。

但 2026-10-29 实测：三个站的下载接口匿名**必然失败**
（创想云 `memberDownload`、Snapmaker `/api/model/download`、MakerOnline 文件接口，都要登录态）。
照字面执行就是每个模型都先白撞一次 401，多等 3–6 秒退避。

而且大量 401 请求本身就是爬虫特征——**撞墙不等于保护账号**，反而更容易被风控盯上。

## 决策

按接口分类，而不是机械地每个请求都先匿名：

| 接口 | 策略 |
|---|---|
| 列表页 / 详情页 | **一律匿名**（本来就不需要登录，且少暴露） |
| 下载类接口 | 首次匿名撞墙 → 记进 `data/auth-needs.json` → 之后同站同接口**直接带登录态** |

### 两层计数（2026-10-29 复核修正）

原来只有一条链，和「失败 3 次才永久放弃」互相矛盾：匿名失败 2 次 + 带登录失败 1 次
就已经 3 次，**「刷新登录态再试」那一步永远轮不到**。改成两个独立计数：

| 计数 | 上限 | 含义 |
|---|---|---|
| `attempts` | 3（本任务内） | 同一次入库里重试了几次 |
| `rounds` | 3（跨轮次） | 这个模型被重新捞起来跑了几轮 |

**一轮** = 一整串升级链跑完：

```
匿名 → 失败 → 退避 2s → 匿名重试 1 次
     → 还失败 → 带登录态
     → 还失败 → 刷新登录态 → 再试 1 次
     → 还失败 → 本轮结束，rounds + 1
```

`rounds` 到 3 → 该模型置 `failed`，不再自动重试。所以刷新登录态那一步**每一轮都会跑到**，
不会再被计数提前掐掉。

## 为什么不是「每次下载都先匿名」

首次撞墙已经证明了「这个接口认不认匿名」，记住结论就够了。重复撞墙：
一是浪费退避时间（每个模型多 3–6 秒），二是把 401 堆成爬虫特征，
与「保护账号」的初衷相反。

`data/auth-needs.json` 落盘（只存站点 + 接口路径 + 布尔，**不含任何凭据**），
所以重启不丢，不会重演撞墙。

## 后果

- **好处**：真的能匿名的地方一律匿名；不产生 401 洪水；首次撞墙是一次性成本
- **代价**：多一个状态文件 `data/auth-needs.json`，站点改版后可能过期
  （登录态失效的 401 会触发刷新重试，不影响正确性）
- **注意**：区分「需要登录」和「登录态过期」——两者都返回 401/未授权，
  但处理不同：前者记标记，后者刷新登录态。判据是**刷新登录态后重试是否成功**
