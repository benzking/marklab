# 0006 · 限速闸门按站独立 + 站点可覆盖

- 状态：已采纳（2026-11-02）
- 相关：0005（控制台 §3 限速口径）、`docs/site-pack.md` §6

## 决策

模型之间的间隔闸门从**一个全局 `nextOkAt`** 改成**每站一个 `nextOkAt`**，并且允许按站覆盖间隔值：

| 层 | 在哪 | 值 | 谁能改 |
|---|---|---|---|
| 全局默认 | `tasks.mjs` `MIN_GAP` / `MAX_GAP` | 60–120 秒 | env / CLI |
| 站点固有 | 包里的 `rate` | 不写就跟随全局 | 改代码 |
| 用户覆盖 | `data/site-config.json` | — | 控制台 / 手改 |

生效顺序 **用户覆盖 > 包 `rate` > 全局默认**。**60 秒地板对三层都生效**，任何来源都压不到 60 以下。

## 为什么

**旧口径**（spec §6 原文）：闸门全局，不分站点。理由是「被封站比慢一天贵」，且当时只有一个队列。

**改的原因**：五个站的风控强度差一个量级——MakerWorld 会弹人机验证，创想云签到接口会回
1088/1089 限流，而 Snapmaker 一直很松。全局一个值只能取最保守的那个，等于让松的站陪紧的站一起慢。
闸门按站独立后，同一时刻仍然只有一条任务在跑（不并发、不增加瞬时压力），只是**松的站不必等紧的站
把间隔走完**。

## 代价与边界

- `data/queue.json` 里 `nextOkAt` 从数字变成 `{ <site>: <ms> }`，**要做一次兼容读取**：读到数字按全局值铺到所有站。
- 全局串行不变：一条任务跑完才取下一条，闸门只决定「能不能取这个站的」。
- 文件之间的 5–10 秒（`grab.mjs`）**不按站配**：已经是秒级，按站调收益为零。
- 搜索 4 次/分、≥15 秒（`search.mjs` `RATE`）**不按站配**：防的是同一个搜索接口，不是整站。
- 不做的：不并发、不做「每站一个队列同时跑」。要并发是另一个决策，得先回答「被封了谁负责」。

## 后果

- 站点包多一个可选字段 `rate: { modelGapSec: [min, max] }`，不写就是跟随全局。
- 控制台「站点包」页每站一个「自定义间隔」输入，留空 = 跟随全局默认。
- spec §6、`AGENTS.md`「不可省」、`docs/site-pack.md` §6 都已同步改成「按站独立 + 可覆盖」。
