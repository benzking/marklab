# 0008 · 聚合搜索：顶栏一个框、五站并行、站点原序

- 状态：已采纳（2026-11-04）
- 相关：0003（匿名优先）、0005（控制台与搜索限速）、0006（按站限速）、0007（运行日志）

## 决策

### 1. 顶栏一个框，两种动作

顶栏只留一个输入框，按内容分派，前端不复制站点正则：

| 输入 | 动作 |
|---|---|
| 能认出模型页的 http(s) 网址 | `POST /api/grab` 入队（行为不变，状态条反馈） |
| 认得出的**作者主页**网址 | 提示「这是作者主页，去控制台建订阅」，不自动建 |
| 认不出的 http(s) 网址 | 原样显示服务端 400 文案（「不认识的站点网址」等） |
| 其它 | 聚合搜索 |

判别交给服务端（`sites.match()` / `parseUserUrl()`），前端只看 `^https?://`。

### 2. 聚合搜索 = 五个独立请求，不是一个批量接口

`POST /api/search`（JSON body `{site, keyword, page?}`）一次只搜一个站，前端并行发五次，谁先回来谁先点亮。

理由：进度天然就是「每站一格」；一站失败不影响其他站；不需要服务端任务注册、不需要 SSE、不需要轮询。每站先取第一页（20 条），前端「显示更多」吃本地余量，余量吃完才请求下一页，最多到第 3 页。

### 3. 请求零排序参数 = 站点自己的默认序

交互式搜索**不传 `sort`**：`search()` 收到 `sort == null` 时不解析、不回落，站点包也不带这个参数。

| 站 | 默认序 |
|---|---|
| 创想云 | 综合趋势 |
| MakerWorld | 相关度（`ORDER[undefined] \|\| 'score'`） |
| Snapmaker | 热门（实测不传 = `sort=hot`，逐条一致） |
| MakerOnline | 相关度 |
| MakeRoad | 站方自己的序（与 `num_like`/`num_download`/`publish_time` 都不同） |

这句人话由站点包的 `searchOptions.defaultLabel` 提供——它是站点事实，不是呈现。
`sorts` 数组的顺序从此**只**决定下拉框排列，不再是「默认序」的声明（`sites/contract.mjs` 注释已改）。

结果页按**站点返回顺序原样展示**，不混排、不跨站归一、不重排。

### 4. 限速：与订阅共用一把闸门，每站 10 次/分

`RATE.perSite = 10`，`rateOf()` 自动推出 6000 ms 间隔。`data/site-config.json` 不再预填覆盖（那六行 `searchPerMin: 6` 是没人记得来历的历史副本，留着等于默认值永不生效）。用户仍可在控制台按站覆盖。

**风险（写在这里是为了将来能查）**：订阅一轮 177 个词，每站从 29.5 分钟降到 17.7 分钟，同样时间多打 67% 请求，而订阅是封站风险最高的路径。要降回来只改 `RATE.perSite` 一个数。

### 5. 手动搜索插队

搜索闸门从 FIFO 改成按站优先队列：`throttle(site, { priority: true })` 插到所有普通请求前面，普通优先级 = 订阅 / 作者页 / 榜单。做法与 `tasks.mjs:358`（手动入队 `lane.unshift`）一致：手动动作永远排下一个。

### 6. 超时

`search` / `userModels` / `feed` 三个入口套 20 秒 `Promise.race`，超时按该站失败返回 `error`。

注意闸门**不持有请求**（它只决定放行节奏），所以卡住的请求不会堵住这一站的队列；超时解决的是另一件事——不让人看着永远转圈，也不让订阅那一轮卡死在某一条上。

### 7. 结果页形态

- 五站各一个分区，站点原序，默认每站 8 条。
- 「显示更多」先吃本地已取的余量，吃完才请求下一页（每请求一次吃一次配额）。
- 一行胶囊同时承担进度与站点筛选：等待 / 搜索中 / 完成（条数滚动）/ 失败（单站重试）。
- 点卡片：已入库 → 本地详情 `#m=<dir>`；未入库 → 原站新标签。
- 未入库卡片带「+ 入库」按钮，点了直接入队。

### 8. 已入库判定放在服务端

`/api/search` 返回每条结果时带 `inLibrary`，来源是 `readdir(LIB)` 的目录名集合（`<site>-<id>`），缓存 5 秒。

不用 `/api/models`：那要逐个读 `model.json` + stat 文件，只为拿一个目录名集合。

### 9. 结果只缓存内存

关键字 → `{结果, 滚动位置}`，最多 5 个词。从详情后退回搜索页零请求；刷新页面就是空态 + 「重新搜索」按钮（刷新多半是误操作，不该偷偷吃配额）。

### 10. 顶栏之外的操作面：右侧悬浮栏

- 「+」加网址：`<dialog>`，纯 CSS 动画；提交走 `POST /api/grab`，成功变「已入队 ✓」，失败红框抖动 + 文案。
- 回到顶部：`scrollY > 300` 才出现。
- 四个数字（订阅 / 候选 / 抓取 / 下载），10 秒轮询 `/api/overview`，`document.hidden` 时跳过；点击进控制台对应页。
- `<860px` 折叠成只剩「+」和回到顶部。

## 不做

- **跨站重复去重**：同一模型多站发布会出两张卡。误合并比多一张卡更烦，v1 不做。
- **跨站混排 / 归一排序**：各站的相关性与热度没有共同刻度，混合排序是假精确。
- **「候选」数字现场重判**：接受最多滞后一轮（`shortcut:` 注释写明上限）。
- **全局「加载更多」**：等于五站各再发一次请求，配额 ×5。
- **新依赖 / 弹窗库 / 前端框架**：`<dialog>` + 纯 CSS 已经够（ADR-0002）。

## 后果

- `web/index.html`：顶栏添加表单移进悬浮栏弹窗；「四站一库」字样删除；placeholder 由 `/api/sites` 动态生成；`web/app.js:179` 侧栏底部那行四站硬编码一并改掉。
- 新增 `GET /api/sites` → `[{site, label}]`，来自站点包（`PACK_FIELDS.label`），**不**按 `discover` 过滤（添加框要收 makeronline.com 的链接）。
- 新增 `GET /api/overview` → 四个计数 + `active: [{url, phase}]` + `recent: [{url, phase}]`（供卡片状态回流）。
- 新增 `POST /api/search` → `{site, keyword, sort, total, items:[… inLibrary]}`，单站失败带 `error`。
- 站点包 `searchOptions` 多一个 `defaultLabel`（可选，字符串）。
- 限速口径：`RATE.perSite` 10，`docs/spec.md`、`docs/adr/0005`、`docs/adr/0006`、`docs/site-pack.md` 同步改。
