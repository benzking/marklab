# 0004 · 重复模型：同站看网址/标题+作者，跨站靠 hash 确认

- 状态：已采纳（2026-10-29，2026-10-30 修订两版）

## 背景

用户要求：「重复模型检测：发布用户 + 模型名；模型文件 hash 值」，
检出后「自动跳过不入库，在任务中有标记，在页面标记其它站也有」。

前两版都翻过车，记在这里免得再犯：

1. **任一 sha256 命中就判整模型重复**（第一版）。实测把
   `library/creality-62985bf125fe4b6423ea5fbc`（8 文件）判成
   `library/creality-646f7660b64b7e9dff1070cb`（6 文件）的重复——两个模型只共享
   3 个通用件，另外 5 个独有、共 61 MB 被整份删掉。
2. **同站比「作者上传文件清单」**（第二版）。清单为空的比例太高
   （MakerWorld 268 个里 158 个、Snapmaker 217 个里 172 个只有打印配置），
   大量模型根本没法比，规则等于半瘫。

## 决策

用户拍板的最终口径：**判重不看清单，看身份；hash 只用来确认。**

### 同站：网址相同 或 标题+作者相同 → 重复

同站的同一个模型，网址本来就一样，`site:id` 相同就是同一个目录。
id 不同但标题+作者相同（改网址重发、镜像号），直接判重复，不必再比文件。

### 跨站：标题+作者相同 → 先记「疑似」；作者件 hash 撞上 → 升级「确认」

跨站同名同作者是最强的先验，但不同站作者可能重名、也可能搬运时改了标题，
所以**不直接拦**，先入库并记疑似，抓到文件后用 hash 确认：

- hash 命中 → 确认重复，删掉本次新目录，库里只留最早那份
- hash 不命中（或没下到文件）→ 停在疑似，两份都留着，页面上互相给链接

「只有字节完全一样才会撞同一个 sha256」——所以 **3mf 只能和 3mf 撞，
stl 只能和 stl 撞**，不需要额外判类型。

### 谁的件算「作者件」

搬运站上常见别人给同一个模型做的打印配置，那不是原作者的东西，不参与比 hash。

| 站点 | 判定方式 |
| --- | --- |
| 创想云 | `fileListPage` 的文件是模型自己的，全部算作者件；配置上的 `isAuth` 是页面上那个「作者」徽标 |
| MakerWorld | `instances[].instanceCreator.uid` 与 `designCreator.uid` 相同才算；不同则 `origin: 'other'` |
| MakerOnline | `print_profiles[].is_author` 就是页面上那个「Designer」徽标；`false` 时该 3mf 标 `origin: 'other'` |
| Snapmaker | `printProfiles[].creatorId` 与模型 `creatorId` 相同才算作者件 |

`origin` 两值：`author`（作者件，默认，含作者自己发布的打印配置）、`other`（别人加的配置）。
只有 `author` 参与 hash 确认。

### 标记存在哪

**不写 `library/`**——`AGENTS.md` 规定 `library/` 是数据、不改已入库文件。
改存外部索引 `data/duplicates.json`：

```json
{ "creality:62985": { "of": "creality:646f", "by": "hash", "at": "…",
  "title": "…", "author": "…", "url": "…", "hashes": ["…"] } }
```

`by` 取值：`meta`（标题+作者疑似）或 `hash`（确认重复）。
`hashes` 留作证据，库里不复制文件。页面在「文件」下面渲染「同模型链接」，
库内的跳详情、被拦下的跳原帖。

## 为什么不是「抓到后直接删掉」

删掉等于白花下载成本，且用户永远看不到「这个模型四个站都有」——
而这恰恰是重复检测最有价值的产出。

## 后果

- **好处**：同站判重零成本（`site:id` / 标题+作者）
- **好处**：跨站不再靠清单，只有真·同字节才删目录
- **好处**：不动 `library/`，符合数据目录约束
- **代价**：跨站作者改名就漏判（用户已接受，不加身份键）
- **代价**：没登录下不到文件时，跨站只能停在疑似，永远不会升级为确认
- **注意**：`duplicates.json` 是索引不是真相，删掉只让页面少显示链接，不影响库完整性
